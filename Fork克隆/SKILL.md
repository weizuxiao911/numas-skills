# fork并clone

把开源贡献任务的目标仓库 **fork 到用户自己的 GitHub 账号**, clone 到用户**明确选择的本地目录**,
配置**双远程**(origin=fork, upstream=原仓库), 并在 clone 出的项目根生成**默认协作规则 AGENTS.md** 与
**日志目录 `.logs/`**, 最后切换工作区到该项目.

**核心原则**: fork / clone 都属于对用户账号与磁盘的**写操作, 必须先取得用户授权再执行**, AI 不擅自决定.

## 前置检查

1. 执行 `gh auth status` 确认已登录; 未登录 → 提示用户先完成「开发准备」技能
2. 从任务消息里读取 `clone 目标目录: <dir>` (用户在欢迎页已选择); 缺失 → 询问用户

## 执行流程

### 1. 确认目标目录 (用户已选择)

- 欢迎页 step2 已让用户用 FilePicker 选好 clone 父目录, 消息里带 `clone 目标目录: <dir>`
- **确认该目录是用户明确选择的本地仓库根目录**; 若不是 → 询问用户
- 展示: 将 clone 到 `<目标目录>/<仓库名>` (仓库名从原仓库 URL 解析, 如 `vsag`)

### 2. 征求授权后执行 fork + clone

先向用户说明将执行的写操作 (fork 到你的账号 + clone 到本地), **取得用户同意后**执行:

```bash
cd <clone 目标目录>
gh repo fork <原仓库 URL> --clone
```

- `gh repo fork` 默认 fork 到当前登录账号; `--clone` 同时 clone 到当前目录
- clone 出的目录名 = 仓库名 (如 `vsag`), 完整路径 = `<目标目录>/<仓库名>`
- 若该路径已存在同名目录, **先询问用户**如何处理 (覆盖 / 换目录 / 跳过 clone)

### 3. 配置双远程

进入 clone 出的项目目录, 确认/配置:

```bash
git remote -v                        # 确认 origin 指向用户自己的 fork
git remote add upstream <原仓库 URL>  # 若 upstream 不存在则添加
```

- `origin` = 用户自己的 fork (提交/推送目标)
- `upstream` = 原仓库 (PR 目标 + 后续同步上游)

### 4. 生成默认协作规则 AGENTS.md (若不存在)

在项目根写入 `AGENTS.md` (**已存在则不覆盖**), 内容为 Numas 默认人与 AI 协作规则:

```markdown
# AGENTS.md — 本项目人与 AI 协作规则

> 用户与 AI 共同维护. 所有行为用户对结果负责; 人决策, AI 仅负责执行.

## 协作铁律

1. **人决策, AI 执行**: 所有功能/方案/边界处理由用户拍板; AI 负责展开事实调查、给建议, 不得替用户做决定.
2. **决策必用 question**: 需要用户决策时, 必须用 question 工具弹选项 (含推荐项, 标 "(推荐)"), 用户点选后再继续; 不得用普通文本提问代替.
3. **关键信息持久化到日志**: 用户与 AI 的交互过程, 把关键信息以日志文件形式追加到 `.logs/{YYYYMMdd}.log`
   (例如 `.logs/20260923.log`), 格式如下:

```text
[2026-09-23 10:00:00] 一句话描述摘要信息
- 按点描述关键信息, 如输入/执行/输出等关键信息内容
```

## 说明

- 本文件在 fork并clone 时自动生成; 用户可随时修改, AI 遵守最新版.
- 所有执行必须取得用户授权; AI 不擅自执行不可逆动作 (删除/推送/强制更新等).
```

### 5. 初始化日志目录

确保项目根存在 `.logs/` 目录 (gitignore 里可加入 `.logs/`, 日志不入库; 若用户希望日志入库则保留).

```bash
mkdir -p .logs
```

### 6. 切换工作区到项目

clone 完成后, 引导前端切换到新项目 (走 chat 的 `setProject` 命令 / 由前端自动切换).

## 汇报

向用户简报:
- fork 地址: `https://github.com/<user>/<repo>`
- 本地项目路径: `<目标目录>/<仓库名>`
- 双远程配置结果
- AGENTS.md 协作规则已生成 + .logs 日志目录已初始化
- 提示可以进行下一步「排查定位」

## 注意事项

- **所有写操作 (fork / clone / remote) 必须先经用户确认** (permission 审批)
- **clone 目标目录必须是用户明确选择的**, 不要自行决定位置
- 网络失败可重试; 如需镜像等替代方案, 先与用户确认
- AGENTS.md 生成后, 后续步骤 (排查定位/方案设计/执行修复/提交PR) 都遵守其中的人决策/question/日志规则
